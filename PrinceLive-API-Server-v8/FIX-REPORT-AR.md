# تقرير الإصلاح والاختبار — PrinceLive API Server v8.0.1

تاريخ التقرير: 2026-11-04

## 1) الأخطاء التي اكتُشفت وأُصلحت

### أخطاء تمنع التشغيل أو تُعطّل ميزة أساسية على Windows 10

1. **مسارات مطلقة داخل إعداد Nginx** — كان `nginx/conf/nginx.conf` (ونسخته `nginx/nginx.conf`) يحتوي
   `error_log "H:/Appli/AmaanLive-Windows/nginx/logs/error.log"` و`alias "H:/Appli/AmaanLive-Windows/srv/hls/"`
   و`alias "H:/Appli/AmaanLive-Windows/srv/uploads/"`. على أي جهاز آخر لا يوجد هذا المسار، فلا يبدأ Nginx
   أو يخدم 404 لكل مقاطع HLS.
   **الإصلاح:** مسارات نسبية إلى بادئة Nginx: `logs/error.log`، `../srv/hls/`، `../srv/uploads/`، ومزامنة النسختين.

2. **`listen 80 reuseport;` غير مدعوم في بناء Nginx لويندوز** — يرفض Nginx الإقلاع بهذا الخيار على Windows.
   **الإصلاح:** `listen 80;` مع تعليق يوضح السبب.

3. **`scripts/stop.bat` لا يعمل** — كان يثبّت المنفذ `3001` ويكتب إلى `/api/stop` الذي يتطلب مصادقة،
   فيرجع 401 ويُطبع «API not responding». كما لم يكن يوقف Nginx ولا خادم Node.
   **الإصلاح:** يقرأ المنفذ وبيانات الإدارة من `config.json`، يرسل Basic Auth، يوقف القنوات ثم Nginx ثم
   عملية Node المستمعة على المنفذ (مع شجرة عملياتها). أُضيف فصل `:stopnode` لضمان التنفيذ بالترتيب.

4. **`ffmpeg` غير موجود في `PATH`** — الحزمة تحمل `ffmpeg.exe` بجانب `server.js` لكن `ffmpegPath` كان `"ffmpeg"`،
   فيفشل التشغيل بـ `spawn ffmpeg ENOENT` إذا بدأ الخادم من مجلد آخر.
   **الإصلاح:** دالة `resolveTool/ffmpegBin` تحل الاسم إلى الملف المرفق بجانب `server.js` ثم تعود إلى `PATH`.

5. **أزرار «تشغيل/إيقاف/إعادة تشغيل القناة المحددة» لا تفعل شيئاً** — العناصر موجودة في `web/admin.html`
   بلا أي مستمع نقر في `web/admin.js`.
   **الإصلاح:** ربط الأزرار الثلاثة بنقاط النهاية `/api/channels/:id/{start,stop,restart}` مع رسالة نتيجة وتحديث الحالة.

6. **صور الأغلفة والشعار عبر `/uploads/`** — كان المسار مخدوماً من Nginx فقط، فيرجع 404 عند فتح الخادم
   مباشرة على منفذ Node أو عند غياب Nginx.
   **الإصلاح:** مسار `/uploads/` في الخادم نفسه مع حماية من الخروج خارج المجلد وأنواع MIME كاملة (منها `webp`).

### أخطاء بيانات وسلوك

7. **رابط القناة كان يُبنى من معرّف المصدر** بدل معرّف القناة في `POST /api/channels` وعند إنشاء القناة
   تلقائياً لمصدر جديد، فيُحفظ `url` خاطئ في `data.json`.
   **الإصلاح:** `/hls/<channelId>/index.m3u8` في الحالتين.

8. **فشل بدء الخادم كان صامتاً** — معالج `server.on('error')` كان يضع `exitCode` فقط دون رسالة عملية،
   فيبدو الخادم «يعمل» بينما لا يستمع على أي منفذ (مثل حظر المنفذ أو نسخة ثانية تعمل).
   **الإصلاح:** رسالة عربية واضحة للحالات `EADDRINUSE` و`EACCES` ثم `process.exit(1)`.

9. **`scripts/allow-lan.bat` يفتح المنفذ 80 دائماً** حتى لو غُيّر `nginxPort`.
   **الإصلاح:** يقرأ `nginxPort` من `config.json`.

10. **`scripts/check.bat` يفحص منفذي 80 و3001 الثابتين** بدل منافذ الإعدادات.
    **الإصلاح:** يقرأ `port` و`nginxPort` من `config.json`.

11. **`scripts/start.bat` لا ينشئ `srv\uploads` ولا ينبّه عند غياب FFmpeg.**
    **الإصلاح:** إنشاء المجلد وفحص وجود `ffmpeg.exe` أو `ffmpeg` في `PATH`.

12. **تضارب توثيق** — كان `README-AR.md` يذكر أن FFmpeg وNginx غير مضمّنين مع أنهما مضمّنان فعلًا.
    **الإصلاح:** تصحيح الفقرة.

### إضافات تشغيل لا تغيّر السلوك الافتراضي
- متغيرات بيئة اختيارية: `PORT`، `HOST`، `DATA_FILE`، `HLS_ROOT`، `LOG_DIR`، `UPLOADS_ROOT`، `FFMPEG_PATH`،
  `FFPROBE_PATH`. القيم الافتراضية ما زالت من `config.json` كما في التشغيل على Windows.

## 2) الاختبارات التي نُفِّذت فعلياً

نُفِّذت على Node.js 20 داخل حاوية Linux مع FFmpeg حقيقي، مقابل نسخة المشروع المعدّلة:

| الاختبار | النتيجة |
| --- | --- |
| `npm test` (scripts/verify-v8.js) | ناجح |
| `node --check` لـ `server.js` و`web/admin.js` و`web/viewer.js` | ناجح |
| صفحة المشاهدين `/` و`/viewer.js` و`/vendor/hls.min.js` | 200 |
| لوحة الإدارة `/admin/` بلا مصادقة / مع مصادقة | 401 / 200 |
| واجهات الإدارة `/api/channels` و`/api/settings` بلا مصادقة | 401 |
| `/api/stop` بلا مصادقة | 401 |
| إنشاء مصدر شبكي → إنشاء قناة مرتبطة تلقائياً | 201 ورابط القناة صحيح |
| تشغيل القناة وبدء FFmpeg وكتابة HLS | 200، `running=true`، `playlistExists=true` |
| تنزيل `index.m3u8` ومقطع `.ts` | 200 |
| إعادة تشغيل القناة | 202 وعاد البث للعمل |
| إيقاف القناة | توقفت فعلياً (`running=false`) |
| `/api/stop` لإيقاف كل القنوات | 200 |
| رفض حذف مصدر مرتبط بقناة | 409 |
| حذف القناة ثم المصدر ثم التحقق من التنظيف | 200 / 200 ورجعت القنوات إلى قنوات المشروع الأصلية |
| رفض جودة غير صالحة ورابط غير مدعوم | 400 |
| `/uploads/<اسم الملف>` | 200 بنوع `image/webp` |
| محاولة قراءة ملف خارج مجلد المرفوعات (`..%2f`) | 403 |
| تشغيل نسخة ثانية على نفس المنفذ | رسالة عربية واضحة + خروج بالرمز 1 |

| حفظ الإعدادات ثم إعادة تشغيل الخادم | القيم محفوظة |

## 3) ما لم يُمكن اختباره في هذه البيئة

- **التقاط USB/DirectShow واختبار الصوت:** لا يوجد كرت التقاط ولا DirectShow في بيئة Linux؛ يجب اختباره على
  Windows 10 مع القطعة الفعلية.
- **Nginx لويندوز:** ملف `.exe` لا يعمل هنا؛ أُصلح الإعداد ولم يُختبر إقلاعه فعلياً على Windows.
- **ملفات `scripts/*.bat`:** بيئة Linux لا تشغّل `cmd.exe`؛ روجعت منطقياً ولم تُنفَّذ فعلياً.
- **جدار الحماية وفتح المنفذ للشبكة المحلية:** خاص بويندوز ويتطلب صلاحيات المسؤول.
