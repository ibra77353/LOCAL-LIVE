# PrinceLive API Server v8 — مرشح إصدار 8.0.1

منصة بث محلي متعددة القنوات تعتمد Node.js وFFmpeg وHLS، مع لوحة أدمن وواجهة مشاهد منفصلتين.

**الحزمة:** لا يُرفَق أي أرشيف `.zip` داخل المستودع؛ تُبنى نسخة **Windows 10/11** عند الحاجة من ملفات المشروع نفسها: `server.js` و`lib/**` و`web/**` و`scripts/**` و`nginx/**` مع `README-AR.md` و`config.json` و`data.json` و`package.json`، بلا ملفات تشغيل (سجلات، مقاطع HLS، رموز، `node_modules`، و`ffmpeg.exe`/`ffprobe.exe`)، وتبدأ بـ`data.json` نظيف: الإعدادات فقط دون مصادر أو قنوات تجريبية.

## نظام التشغيل المدعوم: Windows فقط

> **هذا الإصدار يعمل على Windows 10/11 (64-bit) فقط.** لا يوجد دعم لـ Linux أو macOS ولا للتشغيل داخل حاوية Linux، وليس ذلك قيداً مؤقتاً:
> - الالتقاط كله عبر **DirectShow** (`-f dshow`) والتقاط الشاشة عبر **gdigrab**، وكلاهما من FFmpeg على ويندوز؛ ولا توجد محرّكات V4L2/ALSA/x11grab في المشروع.
> - كل ملفات التشغيل `.bat` (`scripts\start.bat` و`stop.bat` و`check.bat` …) و`nginx\nginx.exe` و`ffmpeg.exe` ملفات ويندوز.
> - لا توجد أي سكربتات shell (`.sh`) ولا أوامر Unix في المشروع، وطبقة الالتقاط `lib/capture/` تسجّل المحرك الوحيد `dshow` في `/api/stats` (`captureEngine: "dshow"`).

على أي نظام آخر يمكن للخادم تقديم الصفحات فقط، لكن إضافة مصدر USB وتشغيل قناة التقاط **لن تعمل**؛ استخدم جهاز Windows للبث الفعلي.

## ما تتضمنه هذه النسخة

- إدارة عدة مصادر التقاط (DirectShow) وHTTP/HLS وRTSP.
- إنشاء قناة تلقائياً عند إضافة مصدر جديد.
- إدارة قنوات متعددة، لكل قناة عملية FFmpeg ومجلد HLS مستقل.
- نموذج ترميز واحد: معدّل بت (Bitrate) لكل قناة يُفرض كسقف صارم، بلا وضع CRF وبلا إعدادات دقة أو FPS أو GOP عامة.
- إعدادات مستقلة لكل قناة: الجودة وBitrate وautoStart وalwaysOn من نافذة القناة، وإعادة تشغيل تلقائية للقناة العاملة فور تغيير أي إعداد ترميز.
- لوحة إعدادات للنظام تشمل x264 Preset وThreads وHLS والمشغل وإعادة التشغيل والخمول والمسارات والمنافذ (أما الدقة ومعدّل البت فلكل قناة).
- اكتشاف أجهزة الالتقاط واستخراج قدراتها واختبار الفيديو والصوت قبل اعتماد الإعداد (DirectShow).
- واجهة مشاهد تعرض القنوات المفعلة وتبدّل بينها.
- واجهات API إدارية محمية بالمصادقة.

## طبقة الالتقاط (Capture Abstraction Layer)

كل تفاصيل الالتقاط معزولة في `lib/capture/`، ولا يبني `server.js` أي وسيط FFmpeg خاص بجهاز التقاط بنفسه:

| الملف | الدور |
| --- | --- |
| `lib/capture/index.js` | الواجهة الموحّدة لمحرك الالتقاط (DirectShow) |
| `lib/capture/dshow.js` | محرك Windows (DirectShow) — وسائط الإدخال وتعداد الأجهزة واختبار الالتقاط |
| `lib/capture/capabilities.js` | تجميع قدرات الجهاز والتوصية |
| `lib/capture/screen.js` | التقاط الشاشة عبر gdigrab |

- **نطاق الدعم:** Windows 10/11 فقط، والمحرك هو DirectShow (يظهر في `/api/stats` باسم `captureEngine: "dshow"`). لا توجد محرّكات أخرى ولا اعتماد على أدوات أو مسارات خاصة بأنظمة تشغيل أخرى.
- **الإدخال:** `-f dshow -rtbufsize 256M` ثم `-framerate`/`-video_size`/الصيغة ثم `-i video=...:audio=...`. «افتراضي» في معدل الإطارات يعني 30 لا 1، ووضع الالتقاط الآمن يُحترم في زر الاختبار كما في وسائط القناة.
- **تعداد الأجهزة:** عبر `-list_devices` في FFmpeg.
- **الصوت:** DirectShow يحمل الصوت مع الفيديو في إدخال واحد (`video=...:audio=...`)، فخريطة الصوت دائماً `-map 0:a:0?`.

## التحقق من الأجهزة المتصلة (USB / DirectShow)

أداة واحدة تمرّ عبر طبقة الالتقاط نفسها التي يستخدمها الخادم، فتطابق نتيجتها ما يظهر في لوحة الإدارة:

```bat
scripts\devices.bat                :: DirectShow — الأجهزة وأوضاع كل جهاز
scripts\devices.bat --no-caps      :: الأجهزة فقط بلا فحص الأوضاع (أسرع)
```

يطبع التقرير: المحرك النشط، إصدار FFmpeg، أسماء أجهزة الفيديو والصوت، ولكل جهاز فيديو الدقات ومعدلات الإطارات والصيغ والتوصية (نفس التوصية التي يطبّقها زر «ضبط تلقائي»). في لوحة الإدارة تُقرأ القائمة من `GET /api/devices` عند فتح نافذة المصدر، وتظهر ملاحظة الخادم إن كانت القائمة فارغة، ويوجد زرّا **اختبار الفيديو** و**اختبار الصوت** (3 ثوانٍ) قبل الحفظ. الاختبار يشغّل الجهاز فعلياً ويرمّز الناتج إلى MPEG-TS بـ`libx264`/`aac` (نفس مكوّنات البث) بدل `-f null`، فلا يعتمد على `null muxer` غير المضمون في نسخ FFmpeg المقلّمة. أي نسخة تشغّل قناة بنجاح تُنجح الاختبار أيضاً.

### على Windows (DirectShow)

- كرت USB أو كاميرا الويب يجب أن يظهر في **إدارة الأجهزة ← Cameras** (أو **Imaging devices**) قبل أن يراه FFmpeg.
- استخدم FFmpeg 64-bit يدعم `dshow` (تأكد بـ `ffmpeg -devices` ثم `scripts\devices.bat`)، وضعه بجانب `server.js` أو في `PATH`.
- إن لم يظهر أي جهاز: فعّل **الإعدادات ← الخصوصية ← الكاميرا ← السماح لتطبيقات سطح المكتب**، ثم أعد تشغيل الطرفية/الخدمة.
- الجهاز المشغول في برنامج آخر (Zoom/Teams/OBS) لا يظهر أو يفشل اختباره؛ أغلق البرنامج أولاً.
- كرت USB الذي يحمل فيديو وصوتاً معاً يظهر مرتين: في «جهاز الفيديو» و«جهاز الصوت»؛ اختر الاثنين ليصل الصوت مع الصورة.
- التصفّح: نافذة المصدر ← اختر الجهاز ← «ضبط تلقائي لأفضل إعدادات» ← اختبار الفيديو/الصوت.

## ضبط مصادر الفيديو على ويندوز (DirectShow) — تفاصيل تقنية

هذا القسم يشرح بالضبط ما يرسله الخادم إلى FFmpeg عند تشغيل قناة USB، وما القيم التي يقبلها كل حقل، وكيف تُقرأ قدرات الكرت، حتى تُضاف المصادر بقيم صحيحة من أول مرة وتعمل القنوات دون أخطاء.

### حقول مصدر USB في `data.json`

الخادم لا يقبل في المصدر إلا حقوله المعروفة (`SOURCE_WRITE_FIELDS` في `server.js`): حقول USB التالية، إضافة إلى `url`/`streamUrl` لمصادر الشبكة و`path` لمصدر الملف. أي حقل آخر يُرفض بـ`400` («خاصية غير متوقعة في إعدادات المصدر»):

| الحقل | الدور | القيم المقبولة والحدود | عند الغياب |
| --- | --- | --- | --- |
| `videoDevice` | اسم جهاز الفيديو كما يعرضه DirectShow حرفياً | إلزامي لمصدر `usb`؛ يُقص عند 300 حرف؛ ويُرفض في فحص القدرات والاختبار إن حمل سطراً جديداً أو `NUL` | يُرفض الحفظ: «جهاز الفيديو مطلوب لمصدر USB» |
| `videoDeviceLabel` | اسم للعرض في اللوحة فقط | نص حتى 200 حرف | يُعرض `videoDevice` |
| `audioDevice` | جهاز الصوت المرافق للكرت | نص حتى 300 حرف | لا صوت: تُضاف `-an` |
| `videoSize` | دقة الالتقاط المطلوبة من الجهاز | يجب أن يطابق `العرضxالارتفاع` بأرقام من 3–4 خانات (`640x480`، `1280x720`، `1920x1080`) | `1280x720` |
| `fps` | معدل إطارات الالتقاط | رقم؛ يُقيَّد بين 1 و60 | 30 (لا 1) |
| `pixelFormat` | صيغة البكسل الخام | `^[a-z0-9_]{2,30}$` مثل `yuyv422` أو `nv12` أو `uyvy422` | لا يُمرَّر `-pixel_format` |
| `vcodec` | اسم codec الالتقاط | `^[a-z0-9_]{2,30}$` مثل `mjpeg` | لا يُمرَّر `-vcodec` |
| `captureSafeMode` | الوضع الآمن | `true` / `false` | `false` |
| `enabled` | تعطيل المصدر بلا حذفه | `true` / `false` | `true` |

- **تبديل الصيغة وcodec تلقائياً:** `mjpeg` و`rawvideo` و`h264` أسماء codec لا صيغ بكسل. إن وضعت واحداً منها في `pixelFormat` ينتقل تلقائياً إلى `-vcodec` (دالة `isCodecName` في `lib/capture/dshow.js`)، وكل قيمة أخرى تذهب إلى `-pixel_format`. لا تُمرَّر القيمة في الموضعين معاً.
- **`videoSize` ليست دقة الخرج:** هي دقة الالتقاط من الكرت فقط. دقة القناة تأتي من «الجودة» (240p…720p) ويُشتق عرض الخرج من نسبة `videoSize` ويُجبَر على الزوجية لأن `yuv420p` يرفض الأبعاد الفردية. لهذا يجب أن تكون `videoSize` مطابقة لوضع يدعمه الجهاز فعلاً، وإلا فشل الالتقاط حتى لو كانت إعدادات القناة سليمة.

مثال مصدر صحيح:

```json
{
  "name": "كاميرا الاستوديو",
  "type": "usb",
  "videoDevice": "USB Video Device",
  "videoSize": "1280x720",
  "fps": 30,
  "pixelFormat": "yuyv422",
  "vcodec": "",
  "captureSafeMode": false,
  "audioDevice": "USB Audio Device",
  "enabled": true
}
```

### وسائط الإدخال التي تُبنى للقناة

عند تشغيل قناة على مصدر `usb` يُبنى الإدخال بهذا الترتيب الثابت (لا يبني الخادم أي وسيط التقاط بنفسه؛ كل شيء من `lib/capture/dshow.js`):

```text
-f dshow -rtbufsize 256M [-framerate <fps>] [-video_size <WxH>] [-pixel_format <fmt>] [-vcodec <codec>] -i video=<videoDevice>[:audio=<audioDevice>]
```

- `-rtbufsize 256M` يمنح DirectShow مخزناً واسعاً يمنع فقدان الإطارات عند أول ثانية من التشغيل.
- `-framerate` و`-video_size` **لا يُمرَّران إطلاقاً** عند تفعيل `captureSafeMode`، لأن فرضهما هو أكثر سبب لرفض الجهاز للتهيئة.
- `-framerate` يُقيَّد بين 1 و60، و«افتراضي» من اللوحة يصبح 30؛ تمرير 0 أو قيمة غير رقمية إلى FFmpeg كان يُنتج طلب إطار واحد في الثانية ويُفشل الالتقاط.
- الصوت لا يأخذ إدخالاً ثانياً: DirectShow يحمله في الإدخال نفسه `video=<video>:audio=<audio>`، ويُخريط دائماً بـ`-map 0:a:0?` بعد إعادة ترميزه `aac` بمعدل `audioSampleRate`/`audioChannels`. بلا `audioDevice` تُضاف `-an` فيخرج البث صامتاً.
- اسم الجهاز يُمرَّر كما هو (بلا علامات تنصيص إضافية، لأن الوسائط تُمرَّر كوسائط عملية مباشرة لا عبر shell)، والمسافات وعلامات الترقيم في الاسم جزء منه: اسم غير مطابق = إدخال لا يفتح.

### قراءة قدرات الكرت وقواعد التوصية

يجري الفحص عبر الأمر نفسه في `scripts\devices.bat` و`GET /api/devices/capabilities?videoDevice=<الاسم>`:

```bat
ffmpeg -hide_banner -f dshow -list_options true -i video="اسم جهاز الفيديو"
```

يحلّل الخادم خرج FFmpeg على stderr بصيغٍ مثل `pixel_format=yuyv422  min s=640x480 fps=30  max s=1280x720 fps=30` وأيضاً `1280x720 @ 30 fps`، ويقبل الدقات بين 160×120 و8192×4320 والمعدلات بين 1 و240، ثم يجمع الأوضاع بلا تكرار.

قواعد «ضبط تلقائي لأفضل إعدادات» (`/api/devices/recommend?device=…`):

| العنصر | القاعدة |
| --- | --- |
| الدقة | أكبر وضع لا يتجاوز 1280×720 (الأخف على المعالج)؛ وإلا أكبر وضع متاح؛ والافتراضي `1280x720` |
| معدل الإطارات | أعلى معدل لا يتجاوز 30؛ وإلا أصغر معدل معروف؛ وإلا 30 |
| الصيغة | أول متاح بالترتيب: `mjpeg` ← `yuyv422` ← `uyvy422` ← `nv12` ← `yuv420p` |
| codec | إن كان `mjpeg` مدعوماً يُعاد `vcodec: "mjpeg"`؛ وإلا يبقى فارغاً |

النتيجة جاهزة للحفظ مباشرة، ومثلها ما يعيده `GET /api/devices/recommend` (وتعيد `/api/devices/options` قوائم الدقات والمعدلات والصيغ لعرضها في القوائم المنسدلة).

### وصفة تشغيل قناة دون أخطاء (بالترتيب)

1. نفّذ `scripts\devices.bat` وتأكد أن الجهاز يظهر باسمه الحرفي في قسم الفيديو (والاسم الصوتي في قسم الصوت إن أردت الصوت).
2. نافذة المصدر ← اختر «جهاز الفيديو» ← **ضبط تلقائي لأفضل إعدادات** ← «اختبار الفيديو» ثم «اختبار الصوت».
3. الاختبار يشغّل الجهاز فعلياً 3 ثوانٍ بـ`-rtbufsize 128M`، ويرمّز إلى MPEG-TS بـ`libx264`/`aac` (نفس مكوّنات البث)؛ نجاحه يعني أن القناة ستفتح الجهاز بنجاح، وفشله يعني خطأ إعداد لا خطأ قناة.
4. احفظ المصدر، ثم افتح القناة واختر جودة (لا «نسخ المصدر»): نسخ المصدر بلا إعادة ترميز مرفوض لالتقاط USB برسالة صريحة، لأن HLS يحتاج ترميزاً إلى `h264`/`aac`.
5. لا تشغّل الجهاز نفسه على قناتين: يُرفض التشغيل بـ«جهاز USB مستخدم بالفعل بواسطة قناة أخرى». والجهاز المشغول في Zoom/Teams/OBS لا يُفتح أصلاً.
6. احتفظ بـ`x264Preset` و`x264Threads` مناسبين للجهاز في الإعدادات العامة؛ قيم غير صالحة تُستبدل تلقائياً بـ`veryfast` و2 خيط مع تحذير في السجل.

### أخطاء شائعة ومعناها والحل

| ما يظهر في سجل القناة | المعنى | الحل |
| --- | --- | --- |
| «الدقة أو معدل الإطارات غير مدعومين من الجهاز» (`Could not set video options` / `Error setting option video_size\|framerate`) | الجهاز يرفض `-video_size`/`-framerate` المطلوبين | استخدم «ضبط تلقائي»، أو فعّل «الوضع الآمن» ليُترك الجهاز على وضعه الافتراضي |
| «صيغة البكسل المطلوبة غير صالحة» (`not a valid pixel format`) | `pixelFormat` غير مدعوم من الكرت (أو خاطئ الموضع) | اختر `yuyv422` أو `mjpeg`، أو اتركه افتراضياً |
| «مُرمِّز libx264 غير متوفر في نسخة FFmpeg المستخدمة» | نسخة FFmpeg بلا `libx264` | استخدم نسخة FFmpeg المرفقة أو نسخة كاملة 64-bit |
| لا تظهر أجهزة في القائمة أو في `scripts\devices.bat` | FFmpeg بلا `dshow`، أو إذن الكاميرا مغلق، أو تعريف ناقص | راجع «متطلبات واجهات DirectShow» أعلاه |
| فشل الإدخال بلا رسالة عربية (اسم جهاز) | `videoDevice` لا يطابق اسم DirectShow حرفياً | انسخ الاسم من `scripts\devices.bat` حرفياً |
| فشل فتح الجهاز مع «جهاز USB مستخدم بالفعل» | الجهاز محجوز لقناة أخرى أو لبرنامج خارجي | أغلق البرنامج الآخر، واستخدم كرتَين لقناتين متزامنتين |

### تحقق سريع من الطرفية قبل إضافة المصدر

```bat
:: 1) هل يظهر الجهاز باسمه؟
ffmpeg -hide_banner -list_devices true -f dshow -i dummy
:: 2) ما الأوضاع التي يدعمها الجهاز؟
ffmpeg -hide_banner -f dshow -list_options true -i video="اسم جهاز الفيديو"
:: 3) هل يفتح الجهاز بالإعدادات المطلوبة؟ (5 ثوانٍ إلى NUL)
ffmpeg -hide_banner -f dshow -rtbufsize 256M -framerate 30 -video_size 1280x720 -i video="اسم جهاز الفيديو":audio="اسم جهاز الصوت" -t 5 -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -c:a aac -f mpegts NUL
```

إن فشل الأمر الثالث فستفشل القناة حتماً؛ عدّل الدقة/المعدل أو فعّل الوضع الآمن أولاً.

## متطلبات التشغيل

النظام مدعوم على **Windows 10/11 64-bit فقط** ولا يعمل على Linux أو macOS (راجع «نظام التشغيل المدعوم: Windows فقط» أعلاه).

| المتطلب | التفاصيل |
| --- | --- |
| نظام التشغيل | Windows 10/11 64-bit بجلسة سطح مكتب تفاعلية (لازمة لالتقاط الشاشة عبر gdigrab) |
| Node.js | 18 أو أحدث، 64-bit ومطابق لمعمارية FFmpeg |
| FFmpeg | نسخة 64-bit تحوي مدخلَي `dshow` و`gdigrab`، ومُرمِّز `libx264`، ومُرمِّز `aac`، وموّصل `mpegts`؛ هذه المكوّنات نفسها يحتاجها زر اختبار الالتقاط، لذا نجاح تشغيل قناة يعني نجاح الاختبار |
| FFprobe | مستحسن، للتحقق من أبعاد الملفات وتوافق codecs |
| Nginx | `nginx.exe` المرفق داخل `nginx/` ليقدّم الواجهة والبث على منفذ `nginxPort` (80 افتراضياً) أمام خادم Node؛ إن لم يستمع أي خدمة على ذلك المنفذ يظهر تحذير في اللوحة (`nginxBinding` في `/api/status`) |
| المصدر | كرت التقاط USB (DirectShow) أو مصدر HTTP/HLS أو RTSP متاح للخادم |

### متطلبات واجهات DirectShow

DirectShow هو الطريق الوحيد لالتقاط USB في هذا الإصدار، ولا يظهر أي جهاز في اللوحة قبل تحقق الشروط التالية:

1. **دعم `dshow` في FFmpeg:** تأكد بـ`ffmpeg -hide_banner -devices` أن القائمة تضم `dshow`، ثم نفّذ `scripts\devices.bat`؛ النسخ المبنية بلا DirectShow لا ترى أي جهاز مهما كان متصلاً.
2. **ظهور الجهاز في ويندوز:** يجب أن يظهر الكرت في **إدارة الأجهزة ← Cameras** أو **Imaging devices** قبل أن يراه FFmpeg؛ تعريف ناقص يعني جهازاً غير موجود.
3. **إذن الكاميرا لتطبيقات سطح المكتب:** **الإعدادات ← الخصوصية ← الكاميرا ← السماح لتطبيقات سطح المكتب**، ثم أعد تشغيل الطرفية أو الخدمة.
4. **وصول حصري للجهاز:** الجهاز المشغول في Zoom/Teams/OBS لا يُفتح لقناة أخرى ولا ينجح اختباره؛ أغلق البرنامج أولاً، ولا تشغّل الجهاز نفسه على قناتين.
5. **اسم الجهاز كما يعرضه DirectShow:** يُمرَّر حرفياً في `-i video=<الاسم>:audio=<الاسم>` مع `-rtbufsize 256M`، واسم غير مطابق يعني فشل الإدخال.
6. **الصوت مع الفيديو:** إن حمل الكرت صوتاً أيضاً فاختر «جهاز الصوت» ليُضاف إلى الإدخال نفسه (`video=…:audio=…`) ويُخريط بـ`-map 0:a:0?`؛ وبلا جهاز صوت يُحذف الصوت (`-an`).
7. **تقاط الشاشة (`gdigrab`):** يحتاج جلسة سطح مكتب تفاعلية مسجّلة الدخول، ولا يعمل من خدمة Windows تعمل بلا سطح مكتب.
8. **معمارية متطابقة:** FFmpeg 64-bit مع Node.js 64-bit؛ خلط 32/64-bit يمنع تحميل مدخل DirectShow.

## الإعداد الأولي

1. فك ضغط الحزمة في مجلد مستقل، ولا تستبدل ملفات إصدار سابق مباشرة.
2. الإعدادات كلها في `data.json` (قسم `settings`): اضبط `ffmpegPath` و`ffprobePath` و`nginxPath` من لوحة الإدارة أو مباشرةً من الملف. ملف `config.json` للتمهيد فقط (`host` و`hlsRoot` و`admin`)؛ أما `port` و`nginxPort` فمصدرهما الوحيد `settings` في `data.json`.
3. غيّر كلمة المرور بعد أول دخول من لوحة الإدارة: **الإعدادات ← الأمان ← تغيير كلمة المرور** (تُحفظ مشفّرة بـ scrypt في كائن `admin` داخل `config.json`).
4. راجع المنفذين `port` و`nginxPort` وعنوان `host`.
5. تأكد من وجود `nginx/conf/nginx.conf` وأن `proxy_pass` يشير إلى منفذ Node.js.
6. شغّل `scripts/start.bat` أو نفّذ `node server.js` من مجلد المشروع.
7. افتح `http://localhost/admin/` وسجّل الدخول.
8. أضف مصدراً، افحصه واختبره، ثم احفظه. ينشئ النظام قناة مرتبطة به تلقائياً.
9. جدار الحماية: `scripts\start.bat` يفحص القاعدة عند كل تشغيل، وإن لم تكن موجودة يشغّل `scripts\firewall.bat` تلقائياً (نافذة صلاحيات واحدة) لفتح منفذ المشاهدة ولوحة الإدارة. يقرأ المنافذ الفعلية من `data.json` عبر `scripts\ports.js`. يدوياً: `firewall.bat` للسماح، `firewall.bat public` للشبكات العامة أيضاً، و`firewall.bat remove` للإلغاء.
10. عدّل القناة: اختر الجودة (أو «نسخ المصدر») ومعدّل البت، ثم اضبط إعدادات التشغيل.
11. افتح واجهة المشاهد من `/`.

## التشغيل والإيقاف

كل ملفات التشغيل في `scripts\`، وتُشغَّل بالنقر المزدوج أو من موجّه الأوامر، وتقرأ المنافذ من المصدر نفسه الذي يقرأه الخادم.

| الملف | الوظيفة |
| --- | --- |
| `scripts\start.bat` | تشغيل خادم Node ثم Nginx والتحقق من جاهزيتهما فعلياً |
| `scripts\stop.bat` | إيقاف القنوات ثم Nginx ثم خادم Node |
| `scripts\check.bat` | فحص Node وملفات المشروع والمنافذ وملاك العمليات |
| `scripts\restart-nginx.bat` / `stop-nginx.bat` | إعادة تشغيل Nginx أو إيقافه وحده |
| `scripts\firewall.bat` / `allow-lan.bat` | فتح منفذي المشاهدة والإدارة في جدار الحماية (`remove` للإلغاء) |
| `scripts\devices.bat` | تقرير أجهزة الالتقاط: الأسماء، أوضاع الفيديو، والتوصية لكل جهاز |

- مصدر المنافذ الوحيد هو `data.json` (`settings.port` و`settings.nginxPort`) عبر `scripts\ports.js`، وكل ملفات BAT (start/stop/check/firewall/restart-nginx) تقرأ منه، فيستخدم التشغيل والإيقاف المنفذ نفسه دائماً. متغير البيئة `PORT` يبقى له الأولوية كما في `server.js`.
- `start.bat` لا يعلن نجاح التشغيل إلا بعد أن يجيب `/api/status` فعلياً ويستمع Nginx على منفذ المشاهدة؛ وإذا تعذّر تشغيل إحدى الخدمتين يطبع السبب ويعيد رمز خروج `1`.
- `stop.bat` لا يوقف إلا عمليات PrinceLive: خادم Node.js يُعرَف بمسار `%ROOT%\server.js` أو بملف `run/server.pid`، وNginx بمسار `nginx\nginx.exe` داخل المشروع (عبر `scripts\procs.js`). أي عملية أخرى تستخدم نفس المنفذ تُترك كما هي ويُطبع تنبيه باسمها.
- الإيقاف العادي لا يحذف السجلات: `logs\server.log` و`nginx\logs\*.log` تبقى للمراجعة. تُنظَّف فقط مقاطع HLS القديمة في `srv\hls` حتى لا يُعرض بث متوقف.

### التشغيل على Windows

1. تأكد من Node.js 18+ في `PATH`، ومن وجود `ffmpeg.exe` (و`ffprobe.exe` مستحسن) بجانب `server.js`، ومن أن منفذَي `settings.port` و`settings.nginxPort` غير مستخدمين.
2. انقر `scripts\start.bat`. الخطوات التي ينفّذها بالترتيب:
   - يقرأ المنفذين من `data.json` عبر `scripts\ports.js`، ويتحقق من وجود `server.js` و`config.json` وNode.js.
   - ينشئ المجلدات الناقصة: `logs` و`run` و`srv\hls` و`srv\uploads`.
   - إن لم تكن قاعدة `PrinceLive HTTP <nginxPort>` موجودة في جدار الحماية، يستدعي `scripts\firewall.bat` تلقائياً (نافذة UAC واحدة) لفتح منفذ المشاهدة ومنفذ لوحة الإدارة.
   - يشغّل الخادم في نافذة مصغّرة باسم **Prince Live API** (`node server.js`) وينتظر استجابة `GET /api/status` حتى 30 ثانية.
   - ينفّذ `nginx -t`، ويشغّل Nginx إن لم يكن يعمل، ثم ينتظر استماعه على منفذ المشاهدة حتى 10 ثوانٍ.
   - يطبع العنوانين ويعيد رمز خروج `0`، أو يطبع سبب الفشل ويعيد `1`.
3. بعد النجاح: `http://127.0.0.1:<nginxPort>/` لواجهة المشاهدين، و`http://127.0.0.1:<nginxPort>/admin/` للوحة الإدارة، و`http://127.0.0.1:<port>` وصول مباشر إلى خادم Node.
4. للوصول من أجهزة الشبكة المحلية نفّذ `scripts\allow-lan.bat` (يفوّض إلى `firewall.bat` لفتح المنفذين على الشبكة الخاصة)، ثم افتح `http://<IP-الجهاز>:<nginxPort>/`. وللإلغاء لاحقاً: `firewall.bat remove`.
5. للتشخيص فقط يمكن تشغيل الخادم يدوياً: `node server.js` من جذر المشروع؛ في هذه الحالة لا يبدأ Nginx تلقائياً، وشغّله بـ `nginx\nginx.exe -p "%CD%\nginx/" -c conf/nginx.conf`.

### الإيقاف على Windows

انقر `scripts\stop.bat`. ترتيب الإيقاف:

1. يقرأ المنفذين من `data.json`، ثم يطلب `POST /api/stop` من الخادم بترويسة رمز التحكّم المحلي `run\control.token` (مهلة 15 ثانية) لإيقاف كل القنوات وتفريغ مقاطع HLS.
2. يوقف Nginx الخاص بالمشروع فقط عبر `scripts\nginx-stop.bat`.
3. يوقف عملية Node الخاصة بالمشروع (عبر `run\server.pid` أو سطر أوامر يحتوي `server.js`) بـ `taskkill /T /F` ثم يعيد الفحص للتأكد من انتهائها.
4. ينظّف `srv\hls` ويحتفظ بالسجلات، ثم يطبع `Prince Live stopped` ورمز خروج `0`، أو `Prince Live did NOT stop completely` ورمز `1`.

- إن ظهرت رسالة تطلب صلاحيات مسؤول فشغّل `stop.bat` كمسؤول؛ إيقاف عملية Node أو Nginx بدأتها جلسة أخرى يحتاج صلاحية أعلى.
- إذا كان المنفذ مشغولاً ببرنامج آخر لم يبدأه المشروع فسيطبع اسمه ولا يوقفه.

### فحص الحالة قبل التشغيل وبعده

`scripts\check.bat` يطبع: إصدار Node، ووجود `server.js` و`config.json`، وصلاحية JSON وقيم `host` والمنافذ ومسارات FFmpeg وNginx وعدد المصادر والقنوات، ونتيجة `nginx -t`، وحالة استماع المنفذين، وملاك العمليات (Prince Live أم برنامج آخر).

### إعادة تشغيل Nginx أو إيقافه وحده

- `scripts\stop-nginx.bat`: يوقف Nginx الخاص بالمشروع فقط.
- `scripts\restart-nginx.bat`: يفحص الإعدادات أولاً، ثم يوقف نسخة المشروع ويعيد تشغيلها. لا يستخدم `nginx -s reload` لأن ملف الـpid قد يحمل معرّف عملية أخرى.

### بعد تغيير الإعدادات

- تغيير `port` أو `nginxPort` أو مسارات `ffmpegPath`/`ffprobePath`/`nginxPath` يحتاج إعادة تشغيل كاملة: `scripts\stop.bat` ثم `scripts\start.bat` (حفظ الإعدادات يحدّث `nginx\conf\nginx.conf` تلقائياً).
- `x264Preset` و`x264Threads` وإعدادات HLS تُطبَّق فوراً: حفظ الإعدادات يعيد تشغيل القنوات النشطة تلقائياً بها (والقنوات المتوقفة تأخذها عند تشغيلها التالي)، فلا تحتاج إعادة تشغيل الخدمة كلها.
- الجودة ومعدّل البت خاصّان بالقناة وحدها: حفظ القناة يعيد تشغيلها تلقائياً إن كانت تعمل، فتُطبَّق القيم الجديدة فوراً.
- لا تشغّل نسختين من المشروع على المنفذ نفسه: `start.bat` يرفض البدء ويسمّي البرنامج الذي يحتل المنفذ.

## إدارة المصادر والقنوات

- مصدر USB: اختر جهاز الفيديو والصوت، ثم استخدم اكتشاف القدرات والضبط التلقائي. يختبر النظام عدة توليفات قصيرة قبل اختيار أول توليفة تنجح.
- مصدر HTTP/HLS أو RTSP: أدخل الرابط واستخدم اختبار المصدر الشبكي قبل الحفظ.
- لكل قناة مجلد مستقل في `srv/hls/<channelId>`، وتُحذف مقاطعه وقوائمه عند إيقاف القناة، ولا تُخدم ملفات قناة متوقفة أو محذوفة (تُرجع 404).
- رابط قائمة التشغيل: `/hls/<channelId>/index.m3u8`.
- لا يمكن تشغيل جهاز USB نفسه على قناتين في الوقت ذاته؛ ذلك يمنع تعارض الوصول إلى جهاز الالتقاط.
- حذف مصدر مرتبط بقناة مرفوض؛ احذف القناة أولاً.

## إعدادات الترميز: لكل قناة

نموذج الترميز الوحيد في هذه النسخة هو **معدّل بت لكل قناة** (Bitrate) يُفرض كسقف صارم. لا يوجد وضع CRF، ولا إعداد عام للدقة أو معدل الإطارات أو GOP: كل ما يخص الترميز يُقرأ من القناة نفسها، و`الإعدادات` تحتفظ بما هو مشترك فقط: `x264Preset` و`x264Threads` وإعدادات HLS.

معدّل البت يُضبط من **نافذة القناة ← معدّل البت**. التغيير يُطبَّق فوراً: إن كانت القناة تعمل تُعاد للتشغيل تلقائياً بعد الحفظ.

### الإعدادات الخاصة بالقناة (`data.json` ← `channels[]`)

| المفتاح | المعنى | القيم والافتراضي |
| --- | --- | --- |
| `bitrate` | بِتريت القناة (سقف صارم) | نص من نمط `رقم + k` مثل `800k`؛ فارغ أو `null` = قيمة تلقائية حسب دقة الخرج |
| `quality` | جودة الخرج | `copy` أو `source` (نسخ المصدر بلا ترميز)، أو `auto` (= 360p)، أو `240p`/`288p`/`320p`/`360p`/`432p`/`480p`/`720p` |
| `fps` | معدل إطارات القناة | من 1 إلى 60؛ `""` أو `null` = 20 |

- خيارات البِتريت في نافذة القناة: `300k` و`400k` و`500k` و`600k` و`800k` و`1000k` مع خيار «تلقائي». وأي قيمة صالحة عبر API (مثل `1500k`) تُحفظ وتظهر كخيار «الحالي» حتى لا تضيع عند التعديل.
- `fps` يُضبط لكل قناة من نافذة القناة (15/20/25/30/50/60)؛ `""` أو `null` = 20، وأي قيمة خارج 1..60 تُرفض بـ`400`.
- `quality` وصيغة `bitrate` مقيّدتان بما سبق، ويُتحقق منهما عند **الإنشاء والتعديل معاً**، وأي قيمة أخرى تُرفض بـ`400`.

### حقول أُلغيت وتُرفض صراحةً

`encodingMode` و`crfValue` و`crf` (وضع CRF)، و`outputWidth` و`outputHeight` و`outputFps` (إعدادات الدقة العامة) لم يعد لها وجود:

- `POST/PUT /api/channels` و`PUT/POST /api/settings` ترفضها برمز `400` ورسالة «خاصية غير متوقعة…» بدل تجاهلها بصمت.
- `PATCH /api/channels/:id` يقبل `enabled` فقط.
- تُحذف بقايا `outputWidth`/`outputHeight`/`outputFps` من `settings` عند إقلاع الخادم إن وُجدت في `data.json` قديم.
- `gopSeconds` استثناء مقصود: يبقى إعداداً عاماً في `settings` (`0` أو فارغ = تلقائي = طول مقطع HLS)، ويُرفض على مستوى القناة (`POST/PUT /api/channels`) كبقية حقول الترميز العامة.

### ترتيب بناء أمر FFmpeg

1. **الأبعاد:** `copy` = أبعاد المصدر كما هي؛ مقاس مسمّى (`360p`) = ارتفاعه مع عرض مُشتق من نسبة أبعاد المصدر؛ `auto` = 360p. العرض يُجبَر على أن يكون زوجياً (وبحد أدنى 160) لأن `yuv420p` يرفض الأبعاد الفردية.
2. **معدل الإطارات:** `channel.fps` أو 20.
3. **الفلاتر:** `scale=<العرض>:<الارتفاع>,format=yuv420p` بلا `pad`، فلا أشرطة سوداء حول الصورة، ومعدّل الإطارات يُضبط بخيار الخرج `-r` لا بفلتر `fps`.
4. **البِتريت:** `channel.bitrate` كما هو، أو القيمة التلقائية حسب ارتفاع الخرج: `2000k` لـ720p وأعلى، `1000k` لـ480p، `500k` لما دون ذلك. أي قيمة غير صالحة تُستبدل بالتلقائية ويُكتب تنبيه في `logs/server.log`.

### كيف يُطبَّق البِتريت

يُفرض سقفاً صارماً بلا حشو: `-b:v` مع `-maxrate` ومخزن VBV `-bufsize` يساوي **ثانية واحدة** بمعدّل القناة (لا ضعفه)، فلا يقفز الخرج فوق القيمة المختارة بين المقاطع، وبلا `nal-hrd=cbr` حتى تبقى المشاهد الهادئة منخفضة الاستهلاك. وسائط قناة 360p بمعدل 25 إطاراً وبِتريت `800k` ومقطع HLS ثانيتين تبدو هكذا:

```text
-map 0:v:0 -vf scale=640:360,format=yuv420p -c:v libx264 -preset veryfast -tune zerolatency -pix_fmt yuv420p -threads 2
-r 25 -g 50 -keyint_min 50 -sc_threshold 0 -b:v 800k -maxrate 800k -bufsize 800k
-map 0:a? -af aresample=async=1 -c:a aac -b:a 96k -ar 44100 -ac 2
-f hls -hls_time 2 -hls_list_size 6 -hls_delete_threshold 4 -hls_flags delete_segments+independent_segments+program_date_time
-hls_segment_filename <المجلد>/seg_<بادئة-فريدة-لكل-تشغيل>_%05d.ts <المجلد>/index.m3u8
```

- **GOP:** إطار مفتاحي واحد عند بداية كل مقطع HLS (`gop = fps × hlsTime`)، فيبدأ كل مقطع من keyframe.
- **الصوت:** يُعاد ترميزه `aac` بـ96k و44100Hz وستيريو (القيم الافتراضية في الخادم)، ويُحذف (`-an`) حين لا يوجد جهاز صوت.
- **Preset وThreads:** من الإعدادات العامة: `x264Preset` بين `ultrafast`…`slow`، و`x264Threads` بين 1 و64؛ والقيمة غير الصالحة تُستبدل بـ`veryfast` و2 مع تنبيه في `logs/server.log`.
- **وضع الجودة (`x264QualityMode`):** عند تفعيله يُحذف `-tune zerolatency` من وسائط libx264 فيستفيد المرمّز من B-frames وlookahead (حجم أقل بنفس الجودة مقابل تأخير أكبر ثوانٍ)، ويُطبَّق فوراً على القنوات النشطة عند حفظ الإعدادات.
- **نسخ المصدر:** يتم بلا إعادة ترميز (`-c:v copy` مع إعادة ترميز الصوت) للمصادر الشبكية فقط؛ والتقاط USB يُرفض برسالة واضحة تطلب اختيار مقاس، أما ملف الفيديو والتقاط الشاشة فيُعاد ترميزهما بأبعاد المصدر.

### جدول المراقبة

يعرض جدول القنوات لكل قناة «الفعلي / المضبوط» محسوباً على نافذة 12 ثانية من مقاطعها المولّدة، ويُلوَّن بالأحمر عند تجاوز المضبوط بأكثر من 25% (فمقاطع TS تضيف عادةً 7–17% أشغال حاوية فوق معدّل الفيديو).

بطاقة «باندويث الإنترنت المستهلك» تقرأ عدّادات كارت الشبكة **من النظام مباشرةً** بلا `netstat`: `Get-NetAdapterStatistics` عبر PowerShell على ويندوز (عدّادات الكارت نفسها، لا تتأثر بلغة النظام)، و`/proc/net/dev` خارج ويندوز. تُجمع البايتات المستلمة لكل الكروت كل 5 ثوانٍ، ويبدأ الإجمالي من صفر عند كل تشغيل؛ وإن تعذّرت القراءة تظهر «—» بدل تعطيل العيّنة.

### متى تُطبَّق التغييرات

فوراً: حفظ القناة يقارن `sourceId` و`quality` و`fps` و`bitrate`، فإن تغيّر أحدها وكانت القناة تعمل أُعيد تشغيلها تلقائياً (وترد واجهة API الحقل `restarted`). أما `x264Preset` و`x264Threads` وإعدادات HLS فتُطبَّق بحفظ الإعدادات العامة: يقارن الخادم قيمها ويرد حقلي `changedSettings` و`restartedChannels` ويعيد تشغيل القنوات النشطة تلقائياً. وضع «نسخ المصدر» (`copy`) لا يمرّ بعملية ترميز، فلا تؤثر فيه إعدادات البِتريت أو الـGOP.

### مثال من `data.json`

```json
"channels": [
  { "id": "ch_1", "quality": "720p", "bitrate": "1200k", "fps": 25 },
  { "id": "ch_2", "quality": "360p", "bitrate": "" },
  { "id": "ch_3", "quality": "copy" }
]
```

- `ch_1`: 720p بسقف 1200k و25 إطاراً.
- `ch_2`: 360p والبِتريت تلقائي (`500k`) و20 إطاراً.
- `ch_3`: نسخ المصدر بلا ترميز.

## واجهات API الرئيسية

### عامة
- `GET /api/public/settings`
- `GET /api/public/channels`
- `POST /api/public/watch` مع `{ "id": "channelId" }`
- `POST /api/public/heartbeat`
- `POST /api/public/leave`
- `GET /api/status?channelId=<id>`

### إدارة — تتطلب المصادقة
- `GET/POST /api/sources`
- `PUT/DELETE /api/sources/:id`
- `POST /api/sources/test`
- `GET /api/channels`
- `POST /api/channels`
- `PUT/DELETE /api/channels/:id`
- `PATCH /api/channels/:id` مع `{ "enabled": true }` أو `false` — تبديل التفعيل وحده
- `POST /api/channels/:id/start`
- `POST /api/channels/:id/stop`
- `POST /api/channels/:id/restart`
- `GET/PUT/POST /api/settings` — `POST` و`PUT` متكافئان في الحفظ والتطبيق الفوري
- `GET /api/devices`
- `GET /api/devices/capabilities?videoDevice=<name>`
- `POST /api/devices/test`
- `POST /api/devices/test-audio`
- `GET /api/stats`
- `GET /api/logs`

لكل مسار قائمة حقول مسموحة: أي خاصية غير معروفة في `POST/PUT /api/channels` أو `POST/PUT /api/sources` أو `PUT/POST /api/settings` تُرفض بـ`400` (مثل `crf` أو `encodingMode` أو `outputWidth`)، و`PATCH /api/channels/:id` يقبل `enabled` فقط.

## ملاحظات مهمة

- `theme` في `settings` يُطبَّق كصنف على `body` في صفحة المشاهدين واللوحة، والقيم المقبولة `default` و`worldcup` (الأخير معرّف في `web/viewer.css`)، وأي قيمة أخرى تُرفض عند الحفظ.
- `startupConcurrency` عدد القنوات التي تُشغَّل معاً عند الإقلاع (1 = تسلسلي، وهو الأنسب لكرت التقاط واحد)، ويبقى `startupQueueDelayMs` تأخيراً أولياً قبل أول دفعة.
- السجلات عند تشخيص فشل التشغيل من أجهزة خارجية: `logs/server.log` (أوامر تشغيل/إيقاف القنوات مع IP والجهاز والسبب)، و`nginx/logs/access.log` (كل الطلبات)، و`nginx/logs/stream.log` (طلبات HLS وحدها)، و`nginx/logs/error.log` (مستوى info).
- تغيير منافذ Node.js أو Nginx يتطلب إعادة تشغيل الخدمات. يتم تحديث إعداد proxy في `nginx/conf/nginx.conf` عند حفظ الإعدادات.
- إذا ظهر `nginx: [emerg] CreateDirectory() "...\nginx/temp/client_body_temp" failed` فهذا يعني أن مجلد `nginx\temp` غير موجود (يحدث عند نسخ الملفات دون المجلدات الفارغة). الحزمة تضم `nginx/temp/.gitkeep`، و`scripts\start.bat` و`restart-nginx.bat` و`check.bat` تستدعي `scripts\nginx-dirs.bat` الذي ينشئ المجلدات المؤقتة قبل أي فحص. للحل الفوري: أنشئ مجلد `nginx\temp` يدوياً ثم أعد `scripts\start.bat`.
- تغيير الجودة أو البِتريت من نافذة القناة يعيد تشغيل القناة العاملة تلقائياً، وكذلك `x264Preset` و`x264Threads` وإعدادات HLS عند حفظ الإعدادات العامة: القنوات النشطة تُعاد تشغيلها فوراً بالقيم الجديدة.
- وضع «نسخ المصدر» دون إعادة ترميز متاح فقط للمصادر الشبكية في هذه النسخة، وقد يفشل إذا كانت codecs غير متوافقة مع HLS MPEG-TS. اختر 240p/288p/320p/360p/432p/480p/720p عند الحاجة إلى إعادة الترميز.
- عدد القنوات المتزامنة تحدده قدرة CPU وRAM وأجهزة الالتقاط وعرض الشبكة.
- الدخول إلى اللوحة يتم داخل الصفحة عبر `POST /api/login` ويُصدر كوكي جلسة HttpOnly موقّعاً صالحاً 12 ساعة ويُبطَل فوراً عند `POST /api/logout` (بحد أقصى 8 محاولات فاشلة لكل عنوان كل 10 دقائق)؛ ولا يوجد Basic Auth: الجلسة هي المصادقة الوحيدة، وسكربتات الجهاز (مثل `scripts/stop.bat`) تستخدم رمز التحكّم المحلي `run/control.token`. اللوحة مناسبة لشبكة محلية موثوقة فقط؛ لا تعرّضها مباشرة للإنترنت.
- هذه مرشح إصدار 8.0.1. تعداد الأجهزة وبناء أوامر الالتقاط واختبارات الـAPI مغطّاة آلياً (`npm test`)، لكن الالتقاط الفعلي من كرت USB حقيقي عبر DirectShow على Windows 10، وقواعد جدار الحماية، لم تُختبر إلا على جهاز Windows فعلي — استخدم `scripts\devices.bat` وأزرار اختبار الفيديو/الصوت للتحقق على جهازك.


## فحص الحزمة
من مجلد المشروع نفّذ:
```bat
npm test
```
ينفّذ هذا الأمر فحوصاً ثابتة للملفات وJSON والعلاقات الأساسية، ثم يطبع قائمة أجهزة الالتقاط. لا يستبدل اختبار كرت USB والصوت وNginx الحقيقي على الجهاز نفسه.


بيانات الدخول الأولية: اسم المستخدم `admin` وكلمة المرور `admin123` (محفوظة مشفّرة بـ scrypt في `admin` داخل `config.json`). غيّرها بعد أول دخول من **الإعدادات ← الأمان**.

الحزمة تضم نسخة Nginx لويندوز داخل مجلد `nginx/`، لكنها **لا تضم `ffmpeg.exe` ولا `ffprobe.exe`** حتى لا تُستبدل نسخة موجودة عندك؛ ضع `ffmpeg.exe` و`ffprobe.exe` في جذر المشروع بجانب `server.js`. يبحث الخادم عن `ffmpeg` بجانب `server.js` أولاً ثم في `PATH`، ولذلك يعمل التشغيل مباشرةً دون تعديل المسارات.
